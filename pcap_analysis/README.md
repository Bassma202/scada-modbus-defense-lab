# SCADA / Modbus TCP Packet Capture & Telemetry Guide

This guide details the Wireshark display filters and telemetry signatures used to distinguish legitimate operator commands from malicious control override attempts.

---

## 1. Key Wireshark Display Filters

| Analysis Objective | Wireshark Display Filter | Description |
| :--- | :--- | :--- |
| **All Modbus Traffic** | `mbtcp` | Captures all Modbus TCP MBAP traffic on default ports. |
| **Write Function Codes** | `modbus.func_code in {5, 6, 15, 16}` | Flags all control actuation commands (Coil/Register writes). |
| **Pump Speed Register Writes** | `modbus.func_code == 6 && modbus.reference_num == 0` | Isolates speed manipulation on Holding Register 0. |
| **Over-Speed Values (> 3000 RPM)** | `modbus.data.uint16 > 3000` | Flags physical safety violation attempts. |
| **Gateway Exceptions** | `modbus.func_code >= 128` | Flags exception responses generated by the defensive gateway. |

---

## 2. Attack Signatures

### Normal Baseline Traffic
* Request: Transaction ID incrementing, `Unit ID: 1`, `Function Code: 3` (Read Holding Registers).
* Regular polling interval: 1.0s to 5.0s.
* Value changes stay strictly within nominal engineering bounds (1200 - 2400 RPM).

### Adversary Over-speed Attack Signature
* Function Code `0x06` (Write Single Register) targeted at Address `0x0000`.
* Payload data: `0x1194` (4500 RPM) or `0x1388` (5000 RPM).
* Rapid sequence of unauthorized writes without prior telemetry reads.
* Gateway Response: Function Code `0x86` (Error flag set) with Exception Code `0x04` (Slave Device Failure / Blocked by Gateway).
